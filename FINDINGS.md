## 2. Data

### 2.1 The dataset

LLMSTU: 283,913 per-student crops (512×512 letterboxed), one caption + 10 structured
fields per crop, generated by **Qwen3.5-VL**. Sampled at 1 fps from 128 source videos.

> **Provenance note.** The repo elsewhere references `Qwen3-VL`; that belongs to the
> *older* whole-frame `stu_img` pipeline. LLMSTU label records carry `model_confidence`
> but no model-name field. Record the exact model ID in the dataset docs before the
> write-up.

### 2.2 Video identity recovery

Video ID was recoverable from filenames for only 2.3% of frames, which blocked
leak-free splitting. Recovered by appearance-chain tracking (64×24 thumbnails,
Hungarian matching per frame-index group): **128 chains, 4660/4660 anchors correct
(100%)**.
→ `outputs/video_recovery_report.json`

### 2.3 Deduplication and occlusion

1 fps sampling produces 200–500 near-duplicate crops per (video, seat). Run-length
encoding of label tuples + stride: **283,913 → 84,950** crops. Additionally dropped
**13,239** crops where `occluded ∧ face_kpts == 2` (no recoverable face signal).
Per-video occlusion ranges **16.5% – 61.5%**.
→ `outputs/dedup_report.json`, `outputs/DATA_INVENTORY.md`

### 2.4 Splits

Video-wise, never frame- or shard-wise: **73 / 27 / 27 videos** = 59,523 / 12,710 /
12,717 crops → ODVG **36,339 / 9,352 / 9,405** frames. Test split reserved untouched
for the final thesis table.
→ `outputs/splits.json`

**This is the single most important correction versus March.** The old split was 100%
temporally leaked (every val frame within ±2.5 s of a train frame), which invalidated
every detector number derived from it. See the post-mortem §1.

### 2.5 Annotation-completeness audit (2026-07-30)

The crop count (283,913) and the ODVG frame count (36,339) differ by design and are
easy to misread. The ODVG unit is a **source frame**, not a crop:

| stage | count |
|---|---|
| raw LLMSTU crops | 283,913 |
| after dedup (frame *selection*) | 84,950 crops worth |
| ODVG train frames | 36,339 |
| **students annotated in them** | **141,522** |

**Critical design point:** dedup decides *which frames* enter training; it does NOT
strip students from a retained frame. `regen_odvg.py` reads `labels_tracked.jsonl`
(all 283,913 records) for frame contents and uses `labels_dedup.jsonl` only for frame
selection. Were it otherwise, unannotated-but-visible students would become false
negatives and would directly suppress R@1.

Verified three ways:

| check | result |
|---|---|
| ODVG boxes vs `labels_tracked` (seat_id ≥ 0) | 141,522 / 141,522 = 100% |
| ODVG boxes vs **raw untouched shards** | 141,522 / 141,912 = **99.73%** |
| ODVG boxes absent from raw shards | 0 |

The 390 missing students (0.27%, 380 of 36,339 frames) are `seat_id < 0` seat-noise
records. Negligible; no rebuild required.

> **Known limitation — upstream detector recall is unverified.** The above proves the
> pipeline does not *lose* students; it cannot prove LLMSTU's person detector *found*
> them all, since there is no human box ground truth. Proxy check against the old
> pipeline's independent detector over 45,184 shared frames: mean students/frame
> LLMSTU 3.33 vs old 3.56; the old detector found more in 19,079 frames, LLMSTU found
> more in 14,547. Symmetric ~7% disagreement — ordinary detector variance, no evidence
> of a systematic gap. Resolving it would require human box annotation. State this as
> a limitation in the write-up.

## 3. Branch A — caption→box matching

### 3.1 The problem

The old pipeline bound `Student N` to the Nth detection *in detector-confidence
order* — an ordering with no relationship to whatever order the captioner used. One
missed detection shifts every subsequent student by one and silently mislabels the
whole frame.

### 3.2 Matching accuracy — RESOLVED 2026-07-31 (clean, full scale)

Evaluated against LLMSTU exact correspondences, **72,398 frames / 261,397
assignments**, `spatial_weight = 0.0` (pure content-based CLIP matching):

| method | assignment acc | wrong rate |
|---|---|---|
| ordinal (detector-confidence order) | **0.2607** | 0.7393 |
| **hungarian** | **0.7896** | 0.2104 |
| sinkhorn | 0.7896 | 0.2104 |
| ordinal_lr (left-to-right) | 1.0000 † | 0.0000 |

By student count — Hungarian degrades gracefully with crowding, ordinal collapses:

| n students | ordinal | hungarian |
|---|---|---|
| 2 | 0.5020 | 0.9363 |
| 3 | 0.3169 | 0.8617 |
| ≥4 | 0.1932 | 0.7372 |

→ `LLMDet/work_dirs/matching/results_lr_sw0.0.json`

**CITE 0.7896, NOT 0.9231.** The earlier 92.3% came from a sweep with
`spatial_weight = 0.5`, whose spatial term scores 1.0 when a unit's ordinal rank
equals the box's left-to-right rank — and the ground truth *is* ordered
left-to-right by construction, so the prior was feeding the answer into the cost
matrix. Re-running at `spatial_weight = 0.0` costs **13.4 points** (0.9231 →
0.7896) and is the honest number. Ordinal is unaffected at 0.2607, so the
headline contrast is **26.1% → 79.0%, a 3.0× improvement**.

† `ordinal_lr = 1.0` is correct **by construction, not a result**: the benchmark
orders units left-to-right and the GT is built the same way. The tool's own help
documents this. It is reported only to show the benchmark contains that shortcut
— which is precisely why the spatial prior had to be disabled.

**The training arms were never affected**: `build_ablation_odvg.py:313` uses
`CompatibilityWeights()` defaults (`clip=1.0, spatial=0.0`), so ARM B/C labels
were always CLIP-only. The A/B/C ablation and its +17.2 R@1 result stand.

That `ordinal_lr = 1.0` sat unremarked in the results file for a day is another
instance of the post-mortem's central pattern: a shortcut that produces a
*better* number reads as success and draws no scrutiny.

Identical frames, captions, boxes, schedule, LR and seed. **Only the unit→box

**THESIS HEADLINE — matching quality → grounding quality.** Replacing ordinal
unit→box binding with Hungarian assignment raises R@1 from **0.3230 to 0.4954,
a +17.2 point absolute / +53% relative gain**, with everything else held identical.

**The arms move in opposite directions.** ARM A decays monotonically from its first
validation (0.345 → 0.323, peaking at iter 1000); ARM B climbs monotonically and
plateaus (0.417 → 0.495). The gap opens from 7 points to 17–19 points and holds.

This is the signature of a pure label-quality effect: training longer on *correct*
bindings compounds the benefit, training longer on *wrong* bindings compounds the
damage. Nothing else in the two runs differs.

**Control — R@10:** 0.9811 (A) vs 0.9952 (B), a difference of 1.4 points against
R@1's 17.2. Both models localise students almost identically well. The entire
divergence is *attribution*: which description belongs to which student. This is
what makes the result attributable to binding quality rather than to any
capability difference between the two models.

R@5 also separates (0.8978 → 0.9595, +6.2), which was not predicted: cleaner
bindings sharpen the whole ranking, not only the top-1 decision.

### 3.5 FINAL ABLATION TABLE — thesis Table 2

All three arms: identical frames, captions, boxes, schedule, LR, seed, and the same
`odvg_val.jsonl` validation set (the p≥0.9 filter applies to *training* data only).
**Only the caption-unit → box binding differs.**

| arm | binding | train regions | R@1 | R@5 | R@10 |
|---|---|---|---|---|---|
| A | ordinal (detector-confidence order) | 165,013 | 0.3230 | 0.8978 | 0.9811 |
| **B** | **Hungarian (CLIP cost)** | 165,017 | **0.4954** | **0.9595** | **0.9952** |
| C | Hungarian + p≥0.9 filter | 98,526 | 0.4787 | 0.9441 | 0.9913 |

**Result 1 — matching quality drives grounding quality.** Hungarian beats ordinal by
**+17.24 R@1 (+53% relative)**. R@10 differs by only 1.4 points, so the gain is
*attribution*, not detection. This is the thesis's core claim, demonstrated under
single-variable experimental control.

**Result 2 — the confidence filter does not help (negative result).** ARM C scores
**1.67 points below ARM B**. Discarding 40% of assignments to keep only p≥0.9 pairs
loses more from reduced data volume than it gains from higher label purity.

Notably, ARM C still recovers **90.3% of ARM B's gain over ARM A using only 59.7% of
the training regions** — so the calibrator does identify genuinely better pairs; there
simply aren't enough of them to compensate. **Recommendation: use unfiltered Hungarian
(ARM B) in the pipeline.** The calibrator remains useful for flagging low-confidence
assignments at inference, not for pruning the training set.

**Methodological note:** the cheap proxy-consistency metric predicted this ordering
correctly (B 40.2% > C 38.3%), the one case in this project where a proxy metric
anticipated the downstream result rather than misleading. It should still not be
treated as a substitute for the R@1 measurement.

All three arms converged — final two validations within 0.002 of each other in every
case — so no number here is an artifact of a truncated schedule.

### 5.4 Interpreting the phone_use disagreement

The dominant frame-level disagreement is `phone_use → screen_oriented`, 82 frames
(next largest: 5). Investigated 2026-07-30:

- Those frames are **3.7% occluded**, versus 57% for correctly-labelled
  `screen_oriented` and 100% for `uncertain`. Occlusion is *highest* where the
  teacher is most accurate.
- On those 82 frames the annotator recorded `phone_visible = true` (81/82); Qwen3.5
  recorded `phone_visible = false` (0/82).
- 31 of 82 are temporally adjacent to a frame Qwen3.5 *did* call phone_use.

**Resolution (project decision, 2026-07-30):** the annotator inferred phone use from
**gaze direction**, while Qwen3.5 reported on the **visible object**. The phone is
frequently behind the monitor. The two sources are answering different questions
rather than contradicting each other, and both are treated as reliable. The measured
87.4% / 75% figures stand as the reference points; they are **not** to be presented
as teacher error.

**Consequence for modelling:** gaze direction carries the phone-use signal when the
object itself is not visible. This strengthens the case for head-pose/gaze features
in Branch B, and means per-frame object detection alone cannot close the gap.

**Reading this honestly:**
- Frame level, the model reaches **86% of the teacher's accuracy** (0.755 / 0.874).
- Event level, it reaches only **33% of the teacher's recall** (6 / 18). Frame

- It decisively beats the majority control (6 vs 0), so the model is doing real
  work; this is not a degenerate classifier like the March one.
- **On the events it does catch, it is more precise than the teacher**: duration
  error 2.3 s vs 4.7 s, and 1.6 false alerts/hour vs 4.7. The model is
  *conservative* — it under-fires but is accurate when it fires. For an
  instructor-facing alert system that is the preferable failure direction, and
  worth stating as such rather than treating 6/24 as simply bad.
- Ceiling-relative framing for the write-up: 18/24 is the best any student of this
  teacher could do. Report both, never 6/24 alone.

**Two evaluator bugs found and fixed before these numbers were trusted** — both of
the silent-plausibility type this project keeps hitting:

1. `AttentionTransformer(per_frame=...)` was not passed, so it defaulted to
   `False` and returned one label per *sequence* instead of per *frame*. The
   checkpoint loads cleanly either way (identical head shape), so it failed
   silently. Now raises if `per_frame` is false.
2. Features were extracted from the **pre-cropped** image with the whole image as
   the box, while `sequence_builder.py:300-307` extracts from the **full frame
   with `bbox_person`**. That made 16 of 552 dims (8 geometry + 8 posture)
   constant and information-free instead of frame-relative.

Impact of fixing #2 alone: frame accuracy **0.342 → 0.755**, events **0/24 → 6/24**.
The pre-fix numbers would have been reported as a catastrophic model failure.
Lesson repeated: an evaluation harness that silently disagrees with the training
harness produces a confident, wrong answer.

### 6.0b Head-pose features — P0.4 build notes (2026-07-31)

**The gate was passed on a better criterion than the one originally set.** MediaPipe
FaceLandmarker detects a face in only **60%** of LLMSTU crops (vs OpenCV Haar's 25%),
short of the ≥70% gate. But detection rate *per cue class* is itself the strongest
single signal measured in this project:

| cue | face_found | mean pitch |
|---|---|---|
| screen_oriented | **92%** | 35.5 |
| looking_away | 90% | 25.8 |
| phone_use | 62% | 27.5 |
| turned_to_peer | 52% | 16.4 |
| **head_down** | **8%** | 47.3 |

`head_down` 8% vs `screen_oriented` 92% is a near-perfect separator for the class the
event layer most often misses. So `face_found` became an explicit **4th dimension**
(552 → **556**) rather than letting a miss collapse to zeros — that ambiguity between
"no face detected" and "facing forward" is precisely what made the OpenCV backend
useless. Coverage was the wrong thing to gate on; discriminative power is the right
thing.

Implementation notes:
- mediapipe 1.0.0 removed the legacy `mp.solutions` API; the backend uses
  `tasks.python.vision.FaceLandmarker` with `output_facial_transformation_matrixes`,
  which gives pose from the 4×4 transform directly (better conditioned than
  landmarks + solvePnP). Installed with `--no-deps` so numpy/protobuf/torch were
  untouched — verified after install.
- Feed the **full crop**, not a top-fraction slice: 35% → 38% detection,
  50% → 55%, full → 60%. FaceLandmarker runs its own face detector.
- Pose is **precomputed in parallel** (`attention/precompute_head_pose.py`):
  283,913 crops in ~3 min on 96 workers, vs ~11 h inline at ~140 ms/crop.
  Cache → `outputs/head_pose_cache.npz`, 61.9% face_found overall.

> sequences with **median inter-frame gap 4.3 s and 58% of gaps > 2 s**. The 552-dim

## 6c. DIPSER external validation — cue→engagement is SETTING-DEPENDENT (2026-07-31) ★

**The question:** our taxonomy claims only visible behaviour ("the head is down"),
never mental state. That is epistemically clean but leaves the thesis asserting
without evidence that these cues have anything to do with attention loss. DIPSER
carries independent EXPERT engagement ratings (1=low … 5=max, 4 labellers +
self-report), so we can test the link. We never train on those ratings.

**Setup:** 25 usable subjects (1 archive corrupt), 1,825 paired observations. For
each expert label at time *t*, the off-task rate in a ±15 s window. Off-task proxy
fixed **a priori** from DIPSER's own head pose — no face found, |yaw|>30°, or
pitch>30° — deliberately not tuned against the ratings, which would manufacture
the correlation it is meant to test. Ordinal ratings → Spearman + 5,000-permutation test.

| expert rating | n | mean off-task rate |
|---|---|---|
| 1 (lowest engagement) | 1 | 63.5% *(n=1, ignore)* |
| 2 (low) | 758 | 22.6% |
| 3 (middle) | 781 | 21.7% |
| 4 (high) | 214 | **36.2%** |
| 5 (maximum) | 71 | **47.0%** |

**Spearman ρ = +0.172, permutation p < 0.0001.**

→ `work_dirs/attention_temporal_hp/dipser_correlation_metadata.json`

### The correlation is significant and runs BACKWARDS

The hypothesis was ρ < 0 (more off-task cues → lower engagement). The measured
result is the reverse: in DIPSER, **more head movement correlates with HIGHER
expert-rated engagement**, monotonically from rating 3 to 5.

The explanation is not that the cues are meaningless — it is that **their meaning
is specific to the room**:

| cue | computer lab (LLMSTU) | lecture hall (DIPSER) |
|---|---|---|
| head down | disengaged (phone, sleeping) | **note-taking — highly engaged** |
| head turned | turned to peer, off-task | **looking at teacher/board — on-task** |
| head still, facing forward | on-task (facing monitor) | possibly disengaged/zoned out |

In our setting on-task means *facing your monitor*, so stillness is engagement. In a
lecture hall on-task means *tracking the instructor and writing*, so movement is
engagement. The same pixels carry opposite meaning.

### Why this is a valuable result, not a failed experiment

1. **It is the strongest available evidence for the supervisor's reframing.** The
   project claims visible cues, never mental state. This shows *why* that
   discipline is necessary: a system that had hard-coded "head down = inattentive"
   would be confidently wrong in the next room. Quote this when defending the
   taxonomy design.
2. **It bounds the generalisation claim honestly.** Our cue→attention mapping is
   calibrated to a computer lab and must NOT be presented as a general classroom
   attention model. That is a limitation the thesis should state up front rather
   than have an examiner find.
3. **It is consistent with §6b.** Zero-shot SCB transfer also degraded sharply.
   Two independent datasets, same conclusion: the pipeline is setting-specific.

### Caveats — do not overstate this either

- The proxy is crude (3 fixed thresholds) and was chosen a priori; a different
  threshold set could weaken or strengthen ρ. It tests the *concept*, not our model.
- ρ = 0.172 is a **weak** correlation. The honest statement is "significantly
  non-zero and in the opposite direction to the naive expectation", not "engagement
  is predicted by head movement".
- Ratings are heavily skewed (1,539 of 1,825 at levels 2–3) and rating 1 has n=1.
- DIPSER's per-student cameras differ geometrically from a wide lab shot.

### Our MODEL on DIPSER — separately, and confounded

Running the 556-dim temporal model directly (4 subjects, 306 pairs) gave
ρ = −0.023, p = 0.74 — null. Cause: the model predicts off-task on only 0–17% of
DIPSER frames (two subjects: 0.0%), collapsing to the majority class because the
geometry features are far out of distribution — a body box fills ~60% of DIPSER's
640×480 frame versus ~5% for a student in our 2812×1050 wide shot. **That number
measures domain shift, not the cue→engagement link**, and should not be reported as
a validation result. → `dipser_correlation_smoke.json`

### 6d.1 Facial expressions — implemented AND measured against expert labels

Channel: MediaPipe FaceLandmarker supplies the **face box**, a ViT FER model
(`dima806/facial_emotions_image_detection`) then predicts 7 basic expressions

**The honest problem, and the measurement that resolves it.** The thesis names
*boredom, perplexity, curiosity* — **academic** emotions (Pekrun), not the
7 basic **Ekman** expressions any off-the-shelf FER model outputs. Asserting
"we detect boredom" would be unfounded. DIPSER labels emotion with the 9-category
academic scheme, expert-annotated, where **code 1 = Boredom**. So it is testable:

| basic expression | AUROC → expert boredom |
|---|---|
| neutral | 0.522 |
| fear | 0.511 |
| surprise | 0.507 |
| angry | 0.490 |
| sad | 0.474 |
| **happy** | **0.441** (p = 0.0025, permutation) |
| **logistic combination, held-out subjects** | **0.544** |

1,176 paired observations, 301 expert boredom (25.6%). **AUROC 0.544 is barely
above chance.** Only `happy` is significant, and inversely — less happiness,
more boredom — which is directionally sensible but weak.

**Conclusion for the write-up:** the facial-expression channel is implemented and
contributes features, but basic expressions do **not** deliver academic-emotion

### 6d.2 Body language + gaze direction — temporal features, no new labels

`attention/dynamic_features.py`, 7 dims computed **per track** from data already
present (bbox + cached head pose), so no annotation was needed:

| dims | signal | topic requirement |
|---|---|---|
| motion_now / mean / **std** | frame-to-frame box displacement, scale-normalised | **fidgeting** |
| scale_change | Δ box area | **leaning forward/backward** |
| gaze_dev_yaw / pitch / mag | deviation from the student's **own median** head pose | **gaze direction** |

Two design points worth defending:

* **Fidgeting is inherently temporal** — motion *variance* over a window. A
  per-frame feature block could never represent it, which is why the indicator
  was missing rather than merely weak.
* **The gaze baseline is personalised.** A student whose head rests at
  yaw = −15° because that is where their monitor sits is ON task; the identical
  angle for a student facing forward is off task. Using each student's own
  median pose as their task direction needs no monitor calibration, no room
  geometry, and is robust to seating position — which a fixed "screen direction"
  prior is not. Median rather than mean, because the transient look-aways are
  precisely the events we measure deviation *from*.
* Verified on synthetic tracks: with realistic 80/20 on-task dominance,
  gaze_dev_mag separates **0.000 (on-task) vs 0.900 (looking away)**; fidget
  variance rises with induced motion. At a degenerate 50/50 split the median
  baseline is ambiguous — a stated limitation, not a hidden one.

## 9a. External classroom datasets — scoped assessment (2026-07-30)

Surveyed for augmenting LLMSTU. **The blocking issue is domain mismatch:** this
project's setting is a *computer lab* (students facing monitors), whereas nearly all
public classroom datasets are *lecture halls* (hand-raising, writing at desks, facing
a teacher). That difference is exactly why phone use reads as screen orientation here
(§5.4) and why monitor occlusion matters. Naive augmentation would inject a foreign
behaviour distribution.

| dataset | scale | annotations | license | verdict |
|---|---|---|---|---|
| **DIPSER** | 1,311,761 imgs, ≤20 students, univ. classroom | face/body boxes, landmarks, **gaze + head pose**, 5-level attention, 9 emotions, smartwatch HR/IMU | **CC-BY** | ✅ use for head-pose supervision |
| **SCB-Dataset5** | 7,428 imgs / 106,830 labels, 20 classes | YOLO + COCO boxes | ⚠️ non-commercial, no standard license | ✅ use as zero-shot eval target |
| STBD-08 (contributed) | 8,884 imgs / 267,888 anns | boxes, 8 classes | same as SCB | optional extra eval |
| DAiSEE | 9,068 webcam videos, 112 students | 4 affective states × 4 levels | academic | ❌ single-person, no boxes |
| EmotiW | 195 videos, 78 students | engagement 0–1 | academic | ❌ single-person, no boxes |
| ActRec-Classroom | 5,126 imgs, 5 classes | boxes | by request | ❌ lecture hall |
| BNU-LCSAD | 128 videos, 11 classrooms | action/detection/captioning | by request | ❌ lecture hall |

> **Scoping correction (2026-07-31).** An earlier version of this section treated
> Branch A (caption→box matching) as "the thesis's central claim" and concluded that
> one-student-per-image data contributes nothing. That is wrong. `Thesis_Topic.md`
> states the claim as *"spotting attention loss during learning sessions"* and names
> the indicators explicitly: **body language, head pose (looking away, nodding), gaze
> direction, and facial expressions**. That is **Branch B**. Matching is the
> methodological contribution that makes the pseudo-labels sound — real, but
> infrastructure, not the claim.
>
> Consequences: (a) Branch B trains on per-student crop *sequences*, which is exactly
> DIPSER's individual-camera format, so that data is native input, not useless;
> (b) `turned_to_peer` (F1 0.18) and `looking_away` (F1 0.29) ARE head pose and gaze —
> the two indicators the proposal names — so DIPSER targets the project's worst
> weaknesses rather than missing them; (c) the proposal also names **facial
> expressions (boredom, perplexity, curiosity)**, which the 6-class taxonomy does not
> cover at all and DIPSER's 9 emotion categories could fill.

### Recommended scope — three decisions

**1. Do NOT augment the DETECTOR (Branch A) training set.** R@10 is already 0.9952, so
localisation is not the bottleneck; attribution is. (This is a Branch-A-only verdict —
see the scoping correction above; it does NOT extend to Branch B.) Foreign behaviour labels would
dilute the LLMSTU taxonomy validated against human gold, break the clean video-wise
split, and force redoing the leakage analysis. Rejected.

**2. DO use DIPSER for Branch B — and decide per label family, not wholesale.**
Its individual-camera streams are per-student sequences, i.e. Branch B's native input,
and it targets the exact indicators the thesis names. The decision is *which of its
label families to import*:

| DIPSER label family | on-claim? | visible-cue compatible? | verdict |
|---|---|---|---|
| **head pose** (yaw/pitch/roll) | ✅ named in proposal | ✅ geometric, observable | **import** — supervises `HeadPoseEstimator`; fixes the F1 0.18 / 0.29 classes |
| **gaze direction** | ✅ named in proposal | ✅ observable | **import** — and per §5.4 gaze is what carries phone-use when the phone is occluded |
| **facial landmarks / meshes** | supporting | ✅ | import as features |
| **9 emotion categories** | ✅ named ("boredom, perplexity, curiosity") | ⚠️ borderline | **open question** — fills a gap the taxonomy does not cover, but expands scope |
| **5-level attention scale** | ✅ | ❌ inferred mental state | **do not import** — violates the taxonomy's founding principle (`taxonomy.py`: *"we claim 'the student's head is down', never 'the student is not paying attention'"*) |
| ethnicity / age / gender | ✗ | — | **never** — captions were deliberately neutralised of protected attributes |

Note DIPSER carries **human and expert-rated** labels, so the pose/gaze/emotion tracks
may not require Qwen3.5 recaptioning at all — which would sidestep the 87.4% teacher
ceiling entirely for those fields (§5.3).

⚠️ Still unresolved: mixing corpora in Branch B needs its own leakage story (video-wise
splits across two datasets), and DIPSER's capture geometry — per-student cameras at
640×480 — gives a *sharper* view of a face than the wide 2812×1050 lab shot ever will.
Training on evidence quality that does not exist at deployment is a real risk; validate
on LLMSTU-only held-out data, never on a mixed val set.

**3. DO run a cross-dataset zero-shot generalisation test.** Train on LLMSTU, evaluate
the frozen detector on SCB-Dataset with no fine-tuning. This demonstrates the
open-vocabulary grounding transfers to an unseen classroom type — a genuine scientific
claim, and it directly exercises the open-vocabulary property that motivates using
LLMDet at all. Higher thesis value than a marginal gain from more training data.

### Sequencing — both come AFTER the main run

- **Head pose (DIPSER)** is a *Branch B* feature. The detector consumes no pose input,
  so this has **no dependency on the main run in either direction**. It cannot run
  concurrently only because of the 4-GPU cap, which the main run saturates.
- **Cross-dataset test** *requires* a trained detector checkpoint, so it is strictly
  downstream of the main run (ARM B's checkpoint could serve as an interim stand-in).

Therefore: **main run first** (it is the critical path and the last blocker on thesis
Table 1), with DIPSER/SCB download, ODVG conversion, and head-pose integration code
written on CPU *during* the run.

### 9a.2 SCB → ODVG converter — built and validated

`grounding_data/llmstu_tools/scb_to_odvg.py`. Reads the subset's `data.yaml`,
maps SCB class names onto the 6-class taxonomy, emits ODVG with char-offset
`tokens_positive` and the `conversations` field the LMM head requires.

Design choices worth keeping:
- **Phrases are copied verbatim from `regen_odvg.ACTIVITY_PHRASE`.** Using a
  different phrase for the same concept would confound the domain gap with a
  vocabulary gap, and the zero-shot number would measure the wrong thing.
- **Teacher classes are EXCLUDED, not mapped** (`teacher`, `guide`, `blackboard`,
  `boardwriting`, `stand`, `handraising`, …). Folding a teacher's box into a student
  cue would corrupt the evaluation.
- **Unmapped classes warn loudly** rather than dropping silently.
- **Boxes are clipped to the frame.** SCB's YOLO boxes overrun by sub-pixel amounts
  (observed `x1 = -1.1`, `y2 = 657.1` on a 657 px image) — harmless in YOLO, but they
  propagate negative coordinates into ODVG. 33 such boxes in the first subset.

First converted subset (`SCB5-Turn-Bow-Head-2024-9-17`, val):

| | |
|---|---|
| mapping | `BowHead → head_down`, `TurnHead → turned_to_peer` |
| output | 505 images, 3,753 regions (7.43/img) |
| dropped | 0 unmapped, 0 degenerate, 0 empty |
| cue histogram | head_down 540, turned_to_peer 3,213 |
| validation | **0 span errors, 0 bbox errors** across all 3,753 regions |

→ `outputs/odvg_scb_bowturnhead_val.jsonl`

### 9a.3 Head-pose backend — built, but the free option is weak

`LLMDet/attention/head_pose.py`. The stub in `features.py` is now a re-export, so
there is exactly one implementation rather than a stub and a real class that drift.

| backend | status |
|---|---|
| `None` | unavailable, block omitted, 552-dim — existing checkpoints stay loadable |
| `opencv` | **working**, zero new dependencies → 555-dim |
| `mediapipe` | implemented (FaceMesh + solvePnP), **not installed** |
| `6drepnet` | plug point only |

⚠️ **The OpenCV backend detects a face in only 25% of real LLMSTU crops.** Where it
fires the values are sensible (yaw −0.77 = strong left profile, +0.11 = near
frontal), but the other 75% return zeros — and zero is *indistinguishable from
"facing straight ahead"*. Haar cascades are poor on the small, angled, low-resolution
faces typical of a wide classroom shot.

**Consequence: the OpenCV backend is a scaffold, not the fix.** Feeding 75% ambiguous
zeros into the temporal model may not improve `turned_to_peer` / `looking_away` and
could add noise. A metric backend (mediapipe or 6DRepNet) is required for the real
gain. A `pip install mediapipe` dry-run was started and **deliberately abandoned** —
it hung, and perturbing a live thesis training environment for a dependency probe is
not a good trade. Install it deliberately when no run is in flight.

Enabling any backend changes the feature width 552 → 555, which requires rebuilding
sequences and retraining the temporal model. `output_dim()` branches on
`available()`, so a backend that claimed availability then failed would change the
feature width mid-run — hence backends fail loudly at construction.
