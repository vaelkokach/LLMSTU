## 2. Precedence order

When two documents disagree, apply these rules in order:

1. **A later, more specific pre-registered protocol amends an earlier one.** `BRANCH_B_TEST_PROTOCOL.md` (2026-08-01, registered before any Branch-B model read the test split) supersedes `TEST_SPLIT_PROTOCOL.md`'s Branch-B aside (also 2026-08-01, written earlier the same day) — the second document exists specifically to close the gap the first one names. Evidence: `TEST_SPLIT_PROTOCOL.md:24-39` states the gap; `BRANCH_B_TEST_PROTOCOL.md:1-17` states it was fixed; `FINDINGS.md:1371-1391` (§11.1) is the fix itself.
2. **Inside `FINDINGS.md`, higher section numbers win, and the document says so explicitly.** `FINDINGS.md:1367` ("It supersedes the absolute numbers in §4.2, §6.0a, §6e and §6f") and `FINDINGS.md:1128-1135` (§9 preamble, twice rewriting itself to remove stale "blocking"/"dropped" claims) establish self-correction as the document's own convention. Apply it even where a later section forgot to re-state it — see Conflict 1.
3. **The closed/fixed item in a checklist wins over an unrelated open item that restates the same fact.** `FINDINGS.md` §9's "Closed" list (`FINDINGS.md:1137-1151`) and "Still open" list (`FINDINGS.md:1153-1194`) are not automatically reconciled with each other — they were edited at different times (2026-08-01 vs 2026-08-09) by the same rewriting convention in rule 2, and one item slipped through. Resolve by section reference, not by list membership: item 14 (§9) cites no section past `TEST_SPLIT_PROTOCOL.md`, while item 7 (§9) cites §11.1. §11.1/§11.9 win.
4. **`outputs/FINAL_RESULTS_REGISTER.md`'s ✅/⛔ flags are authoritative for citability, but only for entries that exist in it.** Its silence on an entry (e.g., the transformer's Branch-B test macro-F1) is a gap in the register, not a ruling that the number is non-citable — confirm against `FINDINGS.md` prose and `BRANCH_B_TEST_PROTOCOL.md`'s pre-registered system list instead.
5. **A document that explicitly names its own staleness wins the citation decision, but not the number.** `THESIS_FIRST_DRAFT.md:606` says its 0.46/0.66 thresholds differ from the "August 1 register" and "must be normalised" — this tells you the register is stale, but does not itself freeze 0.46/0.66 as final, because no regenerated register exists. Treat both figures as provisional pending register regeneration (Conflict 5) and say so in the write-up.
6. **Generated-output tables outrank prose for the exact value of a number they contain; prose outranks generated tables for numbers the tables omit.** `outputs/thesis_tables_C_D.md` and the `LLMDet/work_dirs/thesis/tables/*.md` files are machine-produced and match `FINDINGS.md` to 3–4 significant figures wherever both report a number — but `table_a_test.md`/`table_a_val.md` never emit a transformer row at all, so for the transformer's macro-F1, `FINDINGS.md:1584` and `THESIS_FIRST_DRAFT.md:556` are the only sources.
7. **Non-checkpoint files in `outputs/` always win over their `.ipynb_checkpoints/*-checkpoint.md` counterparts.** Confirmed by `diff` for all four pairs: three are strictly older, one is currently identical; none is ever newer than its live counterpart.
8. **Operational guides carry no evidentiary weight for numbers.** `INFERENCE_GUIDE.md`, `MODEL_COMPARISON_GUIDE.md`, `LLMDet/README.md` §§5.5–5.8, `LLMDet/matching/README.md`, `LLMDet/ATTENTION_PHASE1.md` exist to show *how to run something*; their worked-example numbers are frequently mid-project snapshots (an interim checkpoint, a 500-frame preliminary sweep, a DDP-shard metric) that later sections retract. Never cite a number from these five files without first finding it, or its correction, in `FINDINGS.md` or `outputs/FINAL_RESULTS_REGISTER.md`.
9. **`Thesis_Topic.md` is final on scope, never final on interpretation.** It fixes the title and the four named indicator families permanently (nothing revises it — it is one line, unedited since 2026-07-29). It is not authoritative on whether the system may be described as measuring "attention loss," "comprehension," or "boredom" as mental states — `to-do list.md:1`, `THESIS_PLAN.md:19-25`, and `THESIS_DEFENSIBILITY_REVIEW.md:76-86` jointly and consistently override that literal reading, and `THESIS_FIRST_DRAFT.md`'s abstract already writes the corrected version.
10. **`THESIS_FIRST_DRAFT.md` is the current synthesis, but it inherits rather than resolves the register's gaps.** Use it as the primary reading of "what the thesis currently says," but check Conflicts 1 and 5 before trusting a specific number it repeats from the register.

## Report

**Five most consequential conflicts found** (severity order):

1. **Conflict 1** — `FINDINGS.md`'s own open-item list (§9 item 14) asserts the Branch-B temporal model has no valid test macro-F1, directly contradicting §11.1/§11.9 of the same file, `BRANCH_B_TEST_PROTOCOL.md`, `outputs/FINAL_RESULTS_REGISTER.md`, and `THESIS_FIRST_DRAFT.md` — all of which report and cite 0.407/0.477/0.500 (transformer/ASRF/MS-TCN-556, test) as valid, pre-registered results. This is the single most consequential conflict because it is the exact question the task was asked to resolve, it sits in the "living" open-items list a future contributor would check first, and it could cause a contributor to either wrongly withhold a citable number or wrongly re-run an already-completed ~2.5h GPU rebuild. Resolution: the Branch-C spec's numbers are correct; item 14 is stale and should be corrected or removed.
2. **Conflict 2** — There is no single well-defined "the deployed dashboard model." Two different defaults exist (runtime-config `ff_det/mstcn_553_facefound` chosen for throughput vs. model-selector `arch/asrf_556_hp` chosen for validation macro-F1), and `THESIS_FIRST_DRAFT.md`'s dashboard section describes only "the strict-loaded MS-TCN checkpoint" without disambiguating feature width or face backend, even though `FINDINGS.md` §9 item 15 already flags this exact ambiguity as unresolved and deliberate.
3. **Conflict 5** — `outputs/FINAL_RESULTS_REGISTER.md`, the project's single citable/non-citable ledger, is measurably stale (alert threshold 0.64/0.48 vs. the later-deployed model's 0.66/0.46; throughput 3.05 FPS vs. 5.77 FPS after striding) and this is independently flagged by two later documents (`THESIS_DEFENSIBILITY_REVIEW.md`, `THESIS_FIRST_DRAFT.md`) without either regenerating it. No frozen, current register exists in the tracked corpus as of this commit.
4. **Conflict 4** — `MARCH_2026_POSTMORTEM.md`, the document whose entire purpose is naming what must never be cited, itself names a now-retracted number (92.3% Hungarian matching accuracy) as the valid replacement for the invalid March figure, one day before that number was shown to share the March pipeline's exact failure signature (a ground-truth leak that reads as a better score).
5. **Conflict 6/7/8 (grouped)** — `THESIS_PLAN.md`, which project memory designates the authoritative roadmap, contains three separate now-false factual claims (dashboard dropped; 570-dim headline model; cite-81.5%-matching) that were all true when written and are all corrected by name in `FINDINGS.md`, yet the roadmap document itself was never edited after any of the three reversals. A contributor who reads only `THESIS_PLAN.md` (as instructed) without also reading `FINDINGS.md` end to end would reconstruct a materially wrong picture of the project's current state on all three points.

**Documents judged actively misleading if read in isolation:**

- **`THESIS_PLAN.md`** — despite (or because of) its designation as the authoritative roadmap, its dated status sections (§§2-4, 8) contain three specific factual reversals (Conflicts 6, 7, 8) that a reader would not know to distrust without independently cross-checking `FINDINGS.md`. Its §1/§7 framing rules remain sound and should still be read first.
- **`FINDINGS.md` §9 item 14** specifically (not the file as a whole, which is otherwise the most reliable document in the corpus) — it restates a resolved problem as unresolved, in the one section titled "Still open," which is exactly where a contributor would look to decide what work remains.
- **`MODEL_COMPARISON_GUIDE.md`** — its temporal-model section cites DDP-era macro-F1 figures the project's own results register marks do-not-cite, and it has no knowledge of MS-TCN, ASRF, or the dashboard model registry at all, despite reading as a complete, current reference for "every trained model."
